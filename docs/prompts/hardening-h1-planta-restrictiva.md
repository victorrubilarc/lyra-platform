== OBJETIVO DE ESTA SESIÓN (Tanda A "planta restrictiva ready") ==
Cerrar los 5 ítems de H1 del sub-épico. Es una sesión GRANDE; si el contexto se llena antes de terminar, consolida y propón dividir en H1a (los dos P1 de app) + H1b (los tres P2). Alcance EXACTO:

**(P1-a) Descarga de adjuntos PROXIED por la API — mata el bug 🔴 de MinIO presigned.**
Hoy `MINIO_ENDPOINT=http://minio:9000` (hostname interno de Docker) se usa para FIRMAR las URLs presigned de descarga (apps/watchlog-api/src/storage/minio-storage.service.ts:24-31, presignedGetUrl:87). El navegador de un usuario en la planta JAMÁS resuelve `minio:9000` ⇒ descargar/previsualizar evidencia está ROTO en prod (nadie lo probó con adjuntos en el EC2). Endpoint actual: `GET /log-entries/:id/attachments/:descriptorId/url` (log-entries.controller.ts:311) devuelve la URL presigned; la web la consume con `fetchAttachmentUrl` (log-entries-api.ts:53) y abre/descarga esa URL directo.
- Agrega `getObject(key): Promise<{ stream/buffer, contentType, size }>` (streaming) a la interfaz abstracta `StorageService` (storage.service.ts) + su impl MinIO (minio-storage.service.ts).
- Nuevo endpoint que STREAMEA el archivo por la API con la MISMA ABAC que `getAttachmentDownloadUrl` (resuelve descriptorId desde los valores persistidos, gate `logentry:view`), fijando `Content-Type`, `Content-Disposition` (attachment vs inline según `?inline=1`), `Content-Length`, `X-Content-Type-Options: nosniff`, y cache privada corta. `@Res` reply para binario (patrón del acta PDF y del logo de branding).
- La web deja de abrir la URL de MinIO y apunta al endpoint proxied (mismo contrato o mínimo cambio). Decide (a): ¿retiras `presignedGetUrl`/`getAttachmentDownloadUrl` o lo dejas como fallback? Recomienda — el objetivo es que MinIO NO necesite exposición alguna (superficie sigue en 1 puerto).
- Efecto buscado: MinIO deja de requerir cualquier acceso desde el navegador. Verifica que subir (ya es proxied, log-entries.controller.ts:284) sigue intacto.

**(P1-b) Rate limiting GLOBAL de API — hallazgo 🔴 DoS de aplicación.**
Hoy solo hay lockout en login/MFA/setup + throttle en password-reset (verificado); cualquier endpoint autenticado o el `/api/branding` público admite fuerza de volumen. Usa `@nestjs/throttler`:
- Guard global con límite GENEROSO por defecto (no estorbe a un operador real) + límites ESTRICTOS en `/auth/*`, endpoints públicos (`/api/branding`, `/api/setup/*`) y subida de adjuntos.
- **Almacenamiento en Redis** (ya existe cache.service.ts / módulo redis) para que sea correcto multi-instancia — NO memoria del proceso. Cabezal `Retry-After` en el 429.
- Decide (b): ¿exceptúas health y SSE (shift-handover stream, EventSource)? Justifica. Cuida no romper el smoke de notificaciones ni el streaming de IA.

**(P2-c) Magic bytes en adjuntos de evidencia — hallazgo 🟡 "stored malware delivery".**
Hoy la subida valida el mimetype DECLARADO por el cliente (log-entries.service.ts:1354 `acceptMatches(effectiveAccept(cfg), contentType)`), así que un ejecutable renombrado a .png pasa el `accept`. El branding S3 ya resolvió esto: reusa/extrae `sniffLogoContentType` (branding.service.ts) a un helper compartido de magic bytes y valida el CONTENIDO real contra el `accept` del campo para los tipos sniffables (imágenes, PDF, y los que decidas). Decide (c): tipos que NO se pueden sniffear con seguridad (csv/txt/office) — ¿se aceptan por extensión+mime declarado con nota, o se restringen? No sobre-ingenierizar; documenta el criterio.

**(P2-d) Fuentes Sora/Inter SELF-HOSTED — hallazgo 🟡 egress del navegador.**
Hoy apps/watchlog-web/src/styles/main.css:2 hace `@import url("https://fonts.googleapis.com/...")` ⇒ cada navegador de la planta intenta salir a Google (alerta en el SOC del cliente + degrada en air-gap a fuentes de sistema). Hornea los TTF/woff2 de Sora (600/700/800) e Inter (400/500/600) en la imagen web (el acta PDF ya embebe estos TTF localmente por ruta — mismo patrón/fuente de archivos, @expo-google-fonts o descarga a assets). Sirve con `@font-face` local + `font-display: swap`. Ajusta la CSP (quita `https:` de font-src/style-src si queda limpio). Verifica que el look premium NO cambia (mismos pesos).

**(P2-e) Modo de borde DESACOPLABLE — decisión de borde YA tomada (DECISIONS 2026-07-07).**
El Caddy INTERNO (imagen watchlog-web: sirve SPA + proxea /api, HTTP :80) SE MANTIENE. Desacopla el BORDE con un compose STANDALONE (deploy/, nuevo, separado del actual que usa el `edge` compartido del demo) en 3 modos:
- (a) **detrás del proxy del cliente**: publica `watchlog-web` en `127.0.0.1:<port>` (loopback) para que su F5/NetScaler/NGINX/IIS termine TLS. Modo preferido si tiene appliance.
- (b) **nuestro borde con CERTIFICADO CORPORATIVO** montado (`tls /certs/cert.pem /certs/key.pem`, sin ACME — imposible air-gapped).
- (c) el compartido del demo (actual, no se rompe).
Entrega también un **Caddyfile de borde de ejemplo** (modo b) y una **variante NGINX del borde documentada** (decisión COMERCIAL, no técnica: menos fricción en el cuestionario del cliente que estandariza NGINX). `COOKIE_SECURE=true` + `APP_PUBLIC_URL` https se respetan en los tres. **Entregable clave: MATRIZ DE PUERTOS por modo** para el equipo de redes del cliente (qué queda LISTEN en el host por modo; interno = CERO `ports:` ⇒ inexistente en un escaneo).
